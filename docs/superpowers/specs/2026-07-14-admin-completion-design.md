# SaaSBase 前端 admin 收尾设计

## 目标

将现有 `admin` 管理端补成一条可完整走通的业务闭环，覆盖登录、权限拦截、工作台首页、用户管理和部门管理。

本阶段要做到：

- 登录后能稳定进入管理端
- 路由按会话和权限正确拦截
- 工作台首页和布局可以承载真实使用
- 用户管理可以完成查询、查看、状态切换和重置密码
- 部门管理可以完成树浏览、成员查看和基础组织操作
- 无权限页和 404 页能正常工作

## 范围

包含：

- `admin` 登录与会话流
- 路由守卫与权限拦截
- 管理端布局与工作台首页收口
- 用户管理列表、详情、状态切换、重置密码
- 部门树、成员列表、部门基础操作、成员基础操作
- 模块级 API 适配和类型映射
- 页面级 loading、empty、error、403、404 状态

不包含：

- `client` 用户端业务页面
- 生产部署与 CI/CD 配置
- 后端接口改造本身
- 复杂统计看板或装饰性首页增强

## 架构

```text
apps/admin
├── src/modules/auth
├── src/modules/dashboard
├── src/modules/users
├── src/modules/depts
├── src/modules/system
├── src/layouts
├── src/router
└── src/api
```

### 模块边界

- `auth`：登录、退出、会话维护、权限守卫所需的最小状态
- `dashboard`：工作台首屏与快捷入口
- `users`：用户列表、详情和用户操作
- `depts`：部门树、成员列表和组织操作
- `system`：`403`、`404` 和其他通用状态页
- `layouts`：侧边栏、顶部栏和页面壳
- `router`：路由表、元信息和守卫
- `api`：只做后端接口的轻封装，不堆放页面逻辑

### 页面职责

- 页面只负责交互、编排和状态展示
- 查询、筛选、分页和详情状态下沉到模块 composable
- 请求封装和 DTO 映射只放在 `src/api`
- 路由和布局不直接承载业务细节

### 数据流

- 进入应用后先检查会话
- 未登录访问受限页面时跳转登录页
- 登录后进入工作台
- 用户、部门页面各自从 `api` 层取数
- 写操作完成后刷新当前视图的查询条件或当前列表

## 路由

- `/login`：登录页
- `/dashboard`：工作台首页
- `/users`：用户列表
- `/departments`：部门管理
- `/forbidden`：无权限页
- `/:pathMatch(.*)*`：404 页

路由元信息用于声明访问权限：

- `publicAccess` 表示公开页
- `requiredPermission` 表示受限页所需权限

前端权限控制只作为体验层，最终授权仍以后端为准。

## 布局与首页

### 布局

- 使用固定侧边栏 + 顶部信息条 + 内容区的工作台布局
- 左侧只保留工作台、用户、部门三条主线
- 顶部展示当前标题、角色和退出按钮
- 窄屏时侧边栏与顶部信息允许折行，不强行压缩成图标导航

### 工作台首页

- 工作台首页只保留可用信息，不继续扩展成复杂仪表盘
- 首屏内容以登录身份、可访问模块和快捷入口为主
- 空状态要能解释当前页面的用途

## 认证与权限

### 会话

- 登录、退出和会话维护都通过统一的 `auth` 模块完成
- 页面不直接读写 token
- 登录失效后清理内存会话并跳转登录页

### 守卫

- 公开页直接放行
- 未登录访问受限页时跳转登录页
- 已登录但无权限时跳转 `403`
- 未匹配路由时跳转 `404`
- 页面标题跟随路由元信息更新

## 用户管理

### 功能

- 支持按用户名、部门、状态和角色筛选
- 支持分页加载
- 支持查看详情
- 支持启用、停用和重置密码

### 结构

- `src/api/users.ts`：用户接口适配和查询映射
- `src/modules/users/useUsersModule.ts`：列表、详情和操作状态
- `src/modules/users/UserManagementView.vue`：筛选表单、表格、分页和动作入口
- `src/modules/users/UserDetailDialog.vue`：详情弹窗

### 行为

- 筛选后重新请求列表
- 分页时保留当前筛选条件
- 详情通过弹窗展示，不离开列表页
- 状态切换和重置密码完成后刷新当前列表
- 列表失败时保留筛选条件并显示错误状态

## 部门管理

### 功能

- 支持部门树浏览
- 支持成员列表查看
- 支持新增、编辑、移动和删除部门
- 支持添加和移除成员

### 结构

- `src/api/depts.ts`：部门接口适配和查询映射
- `src/modules/depts/useDepartmentsModule.ts`：部门树、成员和操作状态
- `src/modules/depts/DepartmentManagementView.vue`：部门树和成员视图

### 行为

- 左侧部门树可展开并选中
- 右侧成员列表跟随当前选中部门
- 树和成员列表分开加载，互不阻塞
- 删除和移动需要确认，不做静默操作
- 空树和空成员列表都要给出明确状态

## 错误处理

- 认证失效：清理会话并跳转登录页
- 权限不足：进入无权限页
- 资源不存在：展示明确的 404 或空状态
- 列表请求失败：保留当前筛选条件并显示错误状态
- 详情请求失败：在弹窗内展示错误信息
- 表单校验失败：保留字段级错误信息
- 其他后端错误：保留 `code` 和 `message`

## 测试与质量门禁

- 共享契约层继续保持单元测试
- `admin` 的路由守卫、认证流、用户模块和部门模块需要单元测试或组合测试
- 关键路径补 E2E：登录、未登录跳转、权限拦截、用户列表、部门树
- 每次修改至少运行受影响的测试，再补全 lint、typecheck、build

## 完成标准

当以下条件全部满足时，本阶段可视为完成：

- `admin` 已能真实登录并进入工作台
- 路由守卫和错误页工作正常
- 用户和部门两条主链路可以完成核心操作
- 页面具备 loading、empty、error 和无权限状态
- 类型和测试覆盖了核心交互

## Agent Prompt Guide

- 先做认证、路由、用户、部门这条主链路
- 页面先可用，再补体验细节
- 不要把复杂统计看板提前塞进工作台
- 不要把页面逻辑写进 API 层
- 不要把 `client` 或生产发布范围混进这一阶段
