# SaaSBase 前端 admin 用户列表页设计

## 目标

为 `admin` 管理端补齐用户列表页的第一阶段交互，支持真实 API 下的筛选、分页、查看详情和状态切换。

本阶段要做到：

- 用户列表支持按用户名、部门、状态、手机号筛选
- 列表分页与后端 `page`、`size` 对齐
- 详情通过弹窗展示，不跳转离开列表页
- 状态切换和重置密码保留二次确认

## 范围

包含：

- 用户列表页
- 详情弹窗
- 筛选条件
- 分页
- 状态切换
- 重置密码入口
- 查询参数映射

不包含：

- 用户新增
- 用户编辑
- 批量操作
- 权限管理页
- 部门页

## 布局

- 顶部是筛选条，字段固定为用户名、部门、状态、手机号
- 中间是表格，列包含姓名、账号、角色、部门、状态、更新时间和操作
- 底部是分页器
- 点击“查看”后打开居中弹窗，弹窗只展示详情

## 数据流

- 页面初始化时请求用户列表
- 筛选条件变化后重新请求列表
- 分页变化后保留当前筛选条件并刷新列表
- 点击查看后根据用户 ID 请求详情
- 状态切换、重置密码完成后刷新当前列表

## 错误处理

- 列表请求失败：保留当前筛选条件，显示错误状态和重试入口
- 详情请求失败：在弹窗内展示错误信息
- 认证失效：跳回登录页
- 资源不存在：在详情弹窗内给出明确提示
- 其他后端错误：保留 `code` 和 `message`

## 测试与质量门禁

- 查询参数映射必须有单测
- 列表页需要覆盖加载、分页、详情打开的基本组合测试
- 状态切换和重置密码必须覆盖最小验证
- 空数据和错误状态不能让页面崩溃

## 完成标准

当以下条件全部满足时，本阶段可视为完成：

- 用户列表页可以真实接收和展示后端列表数据
- 筛选和分页与后端契约一致
- 详情弹窗只负责查看
- 状态切换和重置密码可执行并能刷新列表
- 页面在空状态和错误状态下保持可用

## Agent Prompt Guide

- 表格负责列表，弹窗负责查看
- 不把编辑和批量操作提前塞进来
- 查询参数必须和后端命名一致
- 详情弹窗不要承载复杂动作
