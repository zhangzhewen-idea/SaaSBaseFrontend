# SaaSBase 前端 admin 工作台收口设计

## 目标

将 `admin` 管理端的首页与平台概览入口收口为一套可理解、可用、可继续扩展的工作台入口，避免首页长期停留在占位状态。

本阶段要做到：

- 登录后默认进入可用的工作台首页
- 工作台首页能展示当前会话、当前租户和可访问模块
- 平台概览页只保留迁移说明，不再承担独立业务
- 首页的快捷入口只保留当前确实可访问的主链路

## 范围

包含：

- `dashboard` 首页重排与内容收口
- `platform/overview` 迁移说明页
- 首页快捷入口与会话信息展示
- 与首页相关的路由元信息微调
- 首页与迁移页的加载、空状态和错误状态

不包含：

- `AdminLayout` 的整体重构
- 权限守卫逻辑改造
- 用户、部门、文件、平台租户的业务页扩展
- `client` 或 `portal` 的内容建设
- 生产发布与 CI/CD 配置

## 当前问题

现有首页能进入，但更像过渡页：

- 首屏内容偏空，工作台价值不明确
- 平台概览页仍带有演示切换按钮，和模板要求不一致
- 首页的入口说明和布局信息没有形成统一的工作台叙事

这会让用户误以为首页还处在“未完成”阶段，即使核心功能已经可以使用。

## 设计原则

- 首页只承载当前可用信息，不扩展成复杂仪表盘
- 入口优先级高于装饰性内容
- 平台概览页保留路由，但明确告知已迁移
- 页面逻辑留在模块内，不上移到布局或路由层

## 页面结构

### `dashboard`

首页分为三块：

1. 会话摘要
   - 当前角色
   - 当前租户名
   - 当前用户标识
   - 当前权限数量

2. 快捷入口
   - 用户管理
   - 部门管理
   - 文件管理
   - 按权限显示可点击项

3. 状态说明
   - 说明这是工作台首页
   - 说明后续数据应来自真实接口
   - 说明当前页面不再放置演示数据

### `platform/overview`

该页只保留迁移说明：

- 说明平台概览已收口到平台租户管理
- 提示用户直接从侧边栏进入平台租户页面
- 不再保留演示状态切换按钮

## 数据流

- 登录成功后进入 `/dashboard`
- 首页从当前会话读取角色、用户和租户信息
- 快捷入口根据会话权限决定是否显示
- 访问 `/platform/overview` 时仅展示迁移说明，不加载独立业务数据

## 路由与导航

- `/dashboard` 作为默认登录后落点
- `/platform/overview` 保留为兼容路由
- 平台管理员仍可从侧边栏进入平台租户管理
- 普通租户管理员不显示平台租户入口

## 错误处理

- 会话不存在：由现有守卫跳转登录页
- 权限不足：由现有守卫跳转无权限页
- 首页信息无法读取：显示空状态说明，不阻断页面使用
- 迁移页无需独立错误态，保持静态说明即可

## 测试与质量门禁

- 首页需要覆盖基本渲染测试
- 快捷入口需要覆盖权限显示测试
- 迁移说明页需要覆盖文案和入口行为测试
- 与本次改动相关的单测通过后再看是否需要补 E2E

## 完成标准

当以下条件全部满足时，本阶段可视为完成：

- 登录后默认进入可用的工作台首页
- 首页内容能解释当前用户处于什么位置、能去哪里
- 平台概览页不再是假页面
- 首页不再依赖演示交互来完成说明

## Agent Prompt Guide

- 先把首页做实，再谈布局重构
- 不把平台租户管理复制到首页
- 不引入新的全局导航模型
- 不把复杂统计提前塞进工作台
