# SaaSBase 前端平台租户管理设计

## 目标

为 `admin` 应用补齐平台侧租户管理的第一版业务闭环，聚焦平台管理员最常用的租户生命周期操作。

本阶段要做到：

- 平台管理员可以查看租户列表
- 可以按基础条件筛选租户
- 可以创建和编辑租户
- 可以启用和停用租户
- 创建、编辑、启停用后的列表状态能及时刷新

## 范围

包含：

- 平台租户列表页
- 平台租户创建弹窗
- 平台租户编辑弹窗
- 启用、停用确认动作
- 平台租户 API 适配
- 列表、表单和操作状态

不包含：

- 平台控制台首页
- 租户详情侧栏
- 权限治理页
- 平台用户管理
- 平台文件管理
- 生产部署与 CI/CD 配置

## 架构

```text
apps/admin
├── src/modules/platform-tenants
├── src/router
└── src/api
```

### 模块边界

- `platform-tenants`：平台租户列表、表单弹窗和操作状态
- `router`：平台租户页面路由和元信息
- `api`：平台租户接口的轻量封装与参数映射

### 页面职责

- 页面只负责筛选、展示、弹窗开关和动作入口
- 列表查询、表单提交、启停用后刷新下沉到模块 composable
- 后端契约映射只放在 `src/api`
- 页面不直接拼接平台接口参数

### 数据流

- 页面初始化时先拉取租户列表
- 筛选变化后重置到第一页并重新请求
- 创建和编辑通过弹窗完成，成功后刷新当前列表
- 启用和停用走确认操作，成功后刷新当前列表

## 路由

- `/platform/tenants`：平台租户列表页

路由元信息用于声明访问权限：

- `requiredPermission` 声明平台租户管理所需权限
- `title` 用于浏览器标题和面包屑

前端权限控制只作为体验层，最终授权仍以后端为准。

## 平台租户管理

### 功能

- 支持按租户名称、租户编码和状态筛选
- 支持分页查看平台租户列表
- 支持创建租户
- 支持编辑租户
- 支持启用和停用租户

### 结构

- `src/api/platformTenants.ts`：平台租户接口适配和参数映射
- `src/modules/platform-tenants/usePlatformTenantsModule.ts`：列表、表单和操作状态
- `src/modules/platform-tenants/PlatformTenantListView.vue`：筛选表单、表格、分页和动作入口
- `src/modules/platform-tenants/PlatformTenantDialog.vue`：创建和编辑弹窗

### 行为

- 列表首次进入时自动加载
- 筛选后重新请求列表并回到第一页
- 创建和编辑使用同一个弹窗，区别只在初始化数据
- 启用和停用必须二次确认，不做静默切换
- 列表失败时保留当前筛选条件并显示错误状态

## API 接入边界

- 平台租户接口统一走 `/api/v1/platform/tenants`
- 列表分页参数遵循平台后端契约，使用 `pageNo` 和 `pageSize`
- 平台侧写操作必须携带 `operatorId`
- 页面不手工拼接平台权限参数
- 不重复定义后端 DTO，只做必要的前端轻适配

## 错误处理

- 列表请求失败：保留筛选条件，显示错误状态和重试入口
- 表单校验失败：保留字段级错误信息
- 创建和编辑失败：在弹窗内展示错误，不关闭弹窗
- 启用和停用失败：保留当前行状态，提示具体错误
- 鉴权失效：交给现有认证守卫处理，跳登录页或无权限页
- 资源不存在：展示明确的空状态或错误提示

## 测试与质量门禁

- 查询参数映射必须有单测
- 列表页需要覆盖加载、筛选、分页和弹窗打开的基本组合测试
- 创建、编辑、启用和停用都要覆盖最小验证
- 空数据和错误状态不能让页面崩溃

## 完成标准

当以下条件全部满足时，本阶段可视为完成：

- 平台管理员可以真实查看和维护租户列表
- 创建、编辑、启用和停用流程可用
- 列表筛选与分页和后端契约一致
- 页面在空状态和错误状态下保持可用
- 类型和测试覆盖了核心交互

## Agent Prompt Guide

- 先做租户列表和操作闭环，不要先扩平台控制台
- 创建和编辑共用一个弹窗
- `operatorId` 不能遗漏
- 启停用必须二次确认
- 不要把平台控制台首页混进这一阶段
